# Presentation slide visual draft assets

Use this when a user asks for HTML/SVG/PNG visual drafts for slides, especially as a planning artifact before editing a live Google Slides deck.

## Workflow

1. Inspect the current deck style first.
   - Use existing thumbnails/contact sheet or exported slides.
   - Capture the background treatment, palette, card radius, typography scale, footer/takeaway style, and slide density.
   - Do not switch to a dark theme or unrelated art direction unless the deck already uses it or the user asks for it.

2. Set a readability contract before generating assets.
   - Full-size slide assets should be readable without zooming.
   - Use fewer words and larger type rather than shrinking text to fit.
   - Treat small labels/snippet citations as optional supporting text, not the main teaching content.

3. Ground teaching visuals in actual artifacts.
   - For best-practice slides, compare real source snippets when available: repository skills, local skills, scripts, live slide text, references, or templates.
   - Show only a short cutoff snippet/citation on the slide, then name the principle it proves.
   - Avoid generic made-up examples when real examples exist in the task context.

4. Generate editable-first visual directions.
   - Produce SVG and PNG assets when useful for review.
   - Recommend rebuilding text/cards as native Google Slides elements for final deck editability.
   - Use raster screenshots only for proof/evidence or source material that cannot be recreated cleanly.

5. Validate with a contact sheet and individual slide spot-checks.
   - Contact sheet is for QA, not the final readability target.
   - Check for clipped text, missing glyph boxes, noisy arrows, cramped cards, theme mismatch, and unreadable body copy.
   - Regenerate after fixes and state what changed.

## Common pitfalls

- Generating a visually polished but off-brand dark slide set for a light deck.
- Keeping too much text and merely reducing font size.
- Showing invented examples when the user asked to compare actual skills or real artifacts.
- Treating the contact sheet as proof that all full-size slides are readable without inspecting likely problem slides.
- Inserting PNG screenshots as final slides when the user needs editable slide text.
